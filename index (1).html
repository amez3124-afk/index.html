ICMP analysis – Step 7 and Step 13

Wireshark showed ICMP Echo Request and Echo Reply packets. The four requests and four replies corresponded to the successful ping test. Ping uses ICMP, rather than TCP or UDP, for these messages.

Figure 2. ICMP packets captured in Wireshark.

ARP packet analysis – Steps 10–12

10a. The standard Ethernet broadcast MAC address is FF:FF:FF:FF:FF:FF. The selected request in the capture was unicast, so this value was not its destination address. 10b. Selecting a destination address highlights its corresponding bytes in the data pane; the broadcast address could not be demonstrated in the selected unicast frame. 10c. The destination MAC address comes before the source MAC address in the Ethernet header. The captured frame also displayed 802.1Q VLAN information. 11a. ARP fields include hardware type, protocol type, hardware and protocol sizes, operation code, sender MAC and IP, and target MAC and IP. 11b. These fields are present, although a target hardware address can be unknown or filled with zeros in a request. 12. An ARP request asks for a hardware address, while an ARP reply supplies the mapping. The sender and target address roles change between request and reply.

Figure 3. ARP request and Ethernet II header.

Figure 4. ARP reply selected for comparison.

DNS and UDP – Steps 15–17

I performed a DNS lookup for kean.edu and inspected a DNS packet in Wireshark. The UDP header showed source port 49664, destination port 53, UDP length 46 bytes and checksum 0x8438 (status: unverified). Destination port 53 is the standard DNS service port.

Figure 5. UDP header with ports and checksum.

TCP and Telnet – Steps 18–22

I enabled the Windows Telnet Client, then attempted telnet obi2.kean.edu. The connection failed on port 23. I examined an alternative TCP capture in Wireshark. The selected packet displayed destination port 55846, checksum 0xb27a (unverified), a 20-byte TCP header, ACK flag, and zero-byte segment length. The source port was not recorded, so Step 22a is incomplete.

22c. TCP includes sequence and acknowledgment numbers, control flags and window information; UDP has a shorter header with ports, length and checksum. TCP supports reliable ordered delivery, while UDP is connectionless.
